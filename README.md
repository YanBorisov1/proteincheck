# ProteinCheck

Scan a protein bar, powder, shake or yogurt and see an honest, explained breakdown of what's in it. ProteinCheck flags products that are mostly sugar, cheap fillers or heavily processed ingredients behind a big "PROTEIN" label.

- **Every verdict is explained.** There are no black-box scores: every finding is a plain-language sentence, and "Why this score?" shows the full formula with each sub-score and each point deducted.
- **Free and open-source (MIT).** No accounts, ads, tracking, paid APIs or backend.
- **Works on low-end phones and offline.** It's an installable PWA. Products you've already scanned are stored in IndexedDB and work without a connection. Camera scanning and OCR load only when you use them.
- **Translatable.** English is complete and Spanish is partial (untranslated text falls back to English). Adding a language means adding one file.

## Quick start

```bash
npm install
npm run dev          # http://localhost:5173
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Development server |
| `npm run build` | Type-check (strict) and build the PWA into `dist/` |
| `npm run preview` | Serve the production build |
| `npm test` | Unit tests (Vitest) |
| `npm run e2e` | End-to-end smoke test (Playwright; builds first) |

The camera needs HTTPS or `localhost`. To test on a phone, deploy `dist/` to any static host (GitHub Pages, Netlify, a school web server…). The app uses hash routing, so no server configuration is needed.

## How to use it

1. **Scan** a barcode with the camera. The app uses the native `BarcodeDetector` where available, with `@zxing/browser` as a fallback, and a torch toggle where the device supports one. You can also **type** the barcode.
2. The product is looked up in [Open Food Facts](https://world.openfoodfacts.org) and cached on the device.
3. If the product isn't found, you can **photograph the label** (Tesseract.js OCR runs on the phone), **correct** the values it read, and get the analysis. A **manual form** is the last resort. The app also links to Open Food Facts' add-product flow so you can contribute the product back.
4. Enter the price to see the **cost per 30 g of protein**, then **compare** 2–4 products side by side.

## How the score works

The **Protein Honesty Score** (0–100) is a weighted average of six sub-scores. The weights are in `src/analysis/config.ts`:

| Sub-score | Weight | Based on |
| --- | --- | --- |
| Protein density | 30% | % of calories from protein (12% → 25 pts, 20% → 50, 35% → 80, 50% → 95, 70% → 100). If estimated PDCAAS < 0.75 (e.g. collagen-based), the % is multiplied by PDCAAS first |
| Protein quality | 20% | Weighted PDCAAS of the detected sources (explicit protein ingredients first, then by position; or by declared %), minus 15 per amino-spiking agent |
| Sugar | 20% | Sugar per 100 g, sugar:protein ratio, polyols, maltitol, sweeteners, sugar-like fillers |
| Additives | 10% | Starts at 100, minus 4 / 12 / 30 per additive of limited / moderate / high concern |
| Processing | 10% | NOVA group (from Open Food Facts or estimated), ingredient count, hydrogenated fat, palm fat |
| Claim accuracy | 10% | Does it meet the EU "source of" (≥12%) or "high protein" (≥20%) threshold it claims or implies? |

Grades: **A ≥ 80, B ≥ 65, C ≥ 50, D ≥ 35, E < 35.** A sub-score with no data is left out and the remaining weights are scaled up. The coverage is shown in the UI. Without protein and energy values the app gives no score at all rather than a misleading one.

The top 3 red flags and good points are ranked by each finding's importance weight, with personal diet conflicts (from Settings) ranked highest.

### Data sources and honesty notes

- **EU claims:** Regulation (EC) No 1924/2006. **Traffic-light thresholds:** UK FSA. **Reference intakes and energy factors:** Regulation (EU) No 1169/2011.
- **PDCAAS/DIAAS ranges** are approximate ballpark figures from FAO (2013) and later studies. They vary with processing.
- **Additive concern levels** are editorial plain-language summaries of current EFSA opinions. Each entry links to the relevant EFSA or EU page. To edit the table, change `scripts/build-additives.py` and run `python3 scripts/build-additives.py`.
- The **NOVA estimate** is a heuristic used when Open Food Facts doesn't provide one.
- Ingredient detection is pattern-based and can miss unusual wording. Corrections are welcome.

ProteinCheck is general information, not medical advice.

## Adding a language

1. Create `src/i18n/locales/xx.ts` exporting a `Messages` object. Copy keys from `en.ts`; any key you leave out falls back to English.
2. Register it in `LOCALES` in `src/i18n/index.ts`.
3. Optionally add translated guides in `src/content/guides.ts` and a Tesseract language code in `src/services/ocr.ts`.

A unit test checks that every finding the engine can produce has an English message.

## Accessibility

Mobile-first layout with tap targets of at least 44–48 px. Grade colours and highlight colours are chosen for WCAG AA contrast in light and dark mode. Colour is never the only signal: badges have text labels and highlights have underlines and labels. The app uses semantic landmarks and native `<details>` / `<dialog>`, labels every control, announces page changes by moving focus to the main region, includes a skip link, and respects `prefers-reduced-motion`.

## Privacy

Everything stays on the device: history in IndexedDB, settings in localStorage. The only network requests go to Open Food Facts (product lookup and search) and, the first time you use OCR, to the CDN that hosts the Tesseract engine and language data.
